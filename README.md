

#  2026全年排产系统

## 一、项目简介

本系统是一个**基于贪心调度策略的多约束排产引擎**，用于解决个人护理与卫生用品的快消制造业的**多产线、多班次、多SKU**的全年排产问题。

系统输入：
- 全年各月的**生产目标规划**（SKU、数量、规格）
- 各产线的**产能数据**（速度、片数规格、品类能力）
- **生产日历**（工作日/休息日）
- **白名单**（强制指定SKU使用特定产线）
- **断点SKU**、**转移SKU**等特殊规则

系统输出：
- **排产明细表**（每个班次生产了哪个SKU、多少数量）
- **排产汇总表**（每个SKU的规划量 vs 实际排产量）
- **未匹配清单**（哪些SKU没排上、原因是什么）
- **产能缺口分析**（按品类、SKU、月份汇总缺口）
- **开机率分析**（每条产线、每个车间、每个工厂的班次利用率）
- **日历布局表**（可视化展示每天每班次的排产情况）

## 三、Def分层讲解

### 第一层：数据加载层（读取原始数据）

| 函数 | 作用 |
|---|---|
| `load_plan_items(path)` | 读取生产目标规划Excel，按(月份+工厂+SKU+品类+规格)汇总规划数量 |
| `load_capabilities(path)` | 读取产能表，构建每个产线的`LineProfile`（能力列表、计数器、min/max片数） |
| `load_calendar(path)` | 读取生产日历，返回每天是否可开工 |
| `load_breakpoint_skus(path)` | 读取断点SKU清单，返回{SKU: 指定工厂}映射 |
| `load_transfer_skus(path, factory)` | 读取转移SKU清单，指定给目标工厂 |
| `load_matching_overrides(path)` | 读取白名单，返回{(工厂,SKU): [CapabilityRow]} 和 所有白名单能力 |
| `register_capability()` | 将一条能力注册到产线profile（更新计数器、min/max） |

---

### 第二层：数据模型层（核心数据结构）

| 类 | 字段 | 作用 |
|---|---|---|
| `PlanItem` | month, factory, sku, product_name, category, subcategory, spec_piece, planned_qty | 代表一个生产目标规划项 |
| `CapabilityRow` | workshop, line_name, source, category, subcategory, piece_count, speed, shift_minutes | 代表一条产线的某项生产能力（如：3号线，片数10片，速度120） |
| `LineProfile` | line_name, capability_rows, min_piece, max_piece, piece_counter, category_counter, subcategory_counter, combo_counter | 代表一条产线的完整档案（包含所有能力+历史偏好计数） |
| `ShiftSlot` | shift_id, line_name, shift_date, shift_name, is_open_day, remaining_minutes, fragments | 代表一个班次槽位（如：5月5日3号线白班） |

---

### 第三层：业务规则层（匹配与兼容性）

| 函数 | 作用 |
|---|---|
| `is_strictly_compatible(item, row)` | 判断SKU和产线能力是否严格兼容（断点SKU规则、清凉湿巾规则、单片规则、一次性内裤规则等） |
| `is_self_produced(item)` | 判断SKU是自产还是外代工（外代工排产优先级低） |
| `infer_target_subcategory(item)` | 根据产品名称推断目标子品类（如"一次性浴巾"） |
| `candidate_capability(item)` | 产线自己的打分函数：遍历所有能力，计算匹配分，返回最佳匹配和能力 |

---

### 第四层：评分算法层（打分与排序）

| 打分项 | 权重 | 说明 |
|---|---|---|
| 来源匹配 | +60（基础） | 必须匹配，否则淘汰 |
| 片数匹配 | 0~140 | 完全匹配140分，每差1片约扣2-8分 |
| 目标子品类 | +220 | 外部指定的高优先级子品类 |
| 子品类匹配 | +90 | SKU的二级分类与产线能力完全一致 |
| 大类匹配 | +45 | SKU的大类与产线能力一致 |
| 无品类匹配 | -20 | 惩罚 |
| 历史偏好（品类） | `counter * 2` | 该类历史上被选中的次数 |
| 历史偏好（子品类） | `counter * 4` | 该子类历史上被选中的次数 |
| 历史偏好（组合） | `counter * 12` | (大类,子类,片数)组合的历史次数 |
| 历史偏好（片数） | `counter * 0.8` | 该片数的历史次数 |

**排序元组（优先级从高到低）：**
```
(phase, -unused_bonus, load_penalty, -score, -speed, shift_date, shift_type)
```
- `phase`：当月开工(0) > 当月休息日(1) > 前月开工(2) > 前月休息日(3)
- `-unused_bonus`：没用过的产线奖励10万分（鼓励分散用工）
- `load_penalty`：已用分钟少的前排（负载均衡）
- `-score`：匹配分高的前排
- `-speed`：速度快的排前
- `shift_date`：日期早的排前
- `shift_type`：白班(0) > 晚班(1)

---

### 第五层：调度算法层（贪心排产）

| 函数 | 作用 |
|---|---|
| `enumerate_candidate_lines(item, profiles, override_map)` | 为SKU找候选产线（白名单优先，否则正常打分） |
| `next_shift_for_line(line_name, month, slots, sorted_shift_ids)` | 按优先级顺序，找该产线下一个还有剩余产能的班次 |
| `schedule_month(month, month_items, profiles, slots, line_slot_index, changeover_minutes, override_map)` | **核心调度函数**：按订单优先级→每订单贪心分配班次→记录生产片段 |

---

### 第六层：班次管理层（时间轴切片）

| 函数 | 作用 |
|---|---|
| `build_shift_slots(calendar_days, profiles)` | 为每条产线×每天×白班/晚班生成`ShiftSlot`对象 |
| `build_line_slot_index(slots)` | 建立`{产线名: [班次ID列表]}`索引 |
| `line_shift_phase(slot, month)` | 判断班次属于哪一档：0当月开工/1当月休息/2前月开工/3前月休息/None不可用 |
| `shift_sort_key(slot, month)` | 班次排序键（phase优先，日期次之，白班优先） |

---

### 第七层：输出报表层（Excel导出）

| 函数 | 作用 |
|---|---|
| `make_fragment_record(...)` | 将一次生产分配转换为字典记录 |
| `build_month_layout_rows(...)` | 将排产片段按"车间→产线→班次"维度重构为日历表格 |
| `append_sheet(wb, title, rows)` | 通用Sheet写入（表头加粗、冻结首行、筛选、自适应列宽） |
| `append_month_layout_sheet(...)` | 专门用于日历布局表（休息日灰底） |
| `export_workbook(...)` | 输出主报表（每月的排产表、明细表、汇总表） |
| `export_capacity_gap_report(...)` | 输出缺口分析（全年汇总、缺口明细、按品类汇总、TOP30 SKU、按月份汇总） |
| `export_utilization_report(...)` | 输出开机率分析（按产线明细、按车间汇总、按工厂汇总、月度总览） |

## 四、关键设计决策说明

| 决策 | 理由 |
|------|-----|
| **贪心+多目标排序** | 不追求全局最优解，但在可接受时间内给出可行解，适合大规模排产 |
| **load_penalty负载均衡** | 避免某条产线过忙、其他闲置，自动轮转 |
| **白名单优先（10000分）** | 业务强控：某些SKU必须指定产线（如断点SKU） |
| **动态创建profile** | 白名单产线不在profiles中时自动创建，保证白名单生效 |
| **前月借班次** | 允许用前月剩余产能补当月不足，提升总体产能利用率 |
| **切产损耗固定分钟** | 同一班次内切换SKU扣固定时间，模拟真实换产成本 |
| **历史偏好计数** | 让系统逐渐"记住"好用的产线组合，实现自学习 |

## 五、使用说明

### 依赖安装
```bash
pip install openpyxl pandas
```

### 运行命令
```bash
python schedule_main.py --base-dir . --output 2026全年排产结果.xlsx --changeover-minutes 10
```

### 参数说明
| 参数 | 默认值 | 说明 |
|---|---|---|
| `--base-dir` | `.` | 源文件所在目录 |
| `--output` | `2026全年排产结果.xlsx` | 输出文件名 |
| `--changeover-minutes` | `10` | 切产损耗分钟数 |

### 输入文件要求
| 文件名 | 必需列 |
|---|---|
| `目标规划_挑战明细.xlsx` | 月份、供应工厂、处理SKU、产品名称、大类、二级分类、规格、规划包数 |
| `产线产能_目标产能计算完成.xlsx` | 车间、部门名称、机器速度.1、片数、数据来源、大类、二级分类（财务）、单班有效时长 |
| `2026工厂生产日历.xlsx` | 日期、月、是否可开工 |
| `匹配补充.xlsx`（可选） | 供应工厂、处理SKU、车间、部门名称、机器速度.1、片数、数据来源等 |
| `断点SKU.xlsx`（可选） | 物料编码、工厂 |
| `小包SKU.xlsx`（可选） | 物料编码 |

## 六、输出文件说明

### 主报表：`2026全年排产结果_挑战明细.xlsx`
每个月份包含3个Sheet：
- `MM月排产表`：日历布局（行=车间+产线，列=1日白班~31日晚班）
- `MM月明细`：每个生产片段的详细记录（日期、班次、产量、耗时等）
- `MM月汇总`：每个SKU的规划量 vs 实际排产量 vs 差异

### 缺口分析：`2026全年排产结果_挑战明细_缺口分析.xlsx`
| Sheet | 内容 |
|---|---|
| 全年生产汇总 | 各厂各类的规划 vs 实际 |
| 缺口明细 | 每个有缺口的SKU详情 |
| 按品类汇总 | 大类维度缺口统计 |
| TOP30缺口SKU | 缺口最大的30个SKU |
| 按月份汇总 | 每月缺口总数 |

### 开机率分析：`2026全年排产结果_挑战明细_开机率分析.xlsx`
| Sheet | 内容 |
|---|---|
| 按产线明细 | 每条产线的开班数、开机率、生产分钟 |
| 按车间汇总 | 车间维度的开机率 |
| 按工厂汇总 | 工厂维度的开机率 |
| 月度总览 | 每月整体开机率 |
